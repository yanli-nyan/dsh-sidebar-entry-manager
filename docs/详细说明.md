# dsh-sidebar-entry-manager 详细说明

> 左侧栏的面板入口会越装越长。本插件给这些行加一层显示开关：关掉的入口从主排消失，但仍可从「更多」菜单打开；偏好存在本机浏览器，刷新和重启后都还在。
>
> 全文所有结论都来自实测或宿主源码，行号出自 `@deepseek-ai/dsh-client-ui-*` `0.2.1-rc.3`。

## 1. 问题

### 1.1 现象

装插件多了以后，左侧栏那一竖排面板入口（插件、自动化任务、以及今后任何注册到 `sidebar.panellist` 的行）会一直往下长，挤压工作区树和底部区域。DSH 本身没有提供任何入口级的显示/隐藏开关：宿主只允许在「更多」菜单里把行 **收起（unpin）**，但这个状态是**内存态**，重载即重置。

### 1.2 目标

1. 能关掉不常用的面板行，关掉后左栏主排不再显示它；
2. 关掉的行仍然能打开（不能变成"藏了就找不回来"）；
3. 偏好落在本机，刷新、重启后保持；
4. 不修改宿主、不修改任何别的插件。

### 1.3 三条硬边界（先讲清楚）

| | 能力 | 为什么 |
| --- | --- | --- |
| ✅ | 隐藏任意非 `plugins` 的面板行 | 行过滤条件 `id === "plugins" \|\| !unpinned.includes(id)`（`dsh-client-ui-sidebar/lib/client.js:471`） |
| ✅ | 被隐藏的入口仍可打开 | 「更多」菜单列出全部可管理入口（`client.js:482-487`） |
| ✅ | 偏好持久化 | `localStorage` 键 `dsh-sidebar-entry-manager:prefs` |
| ❌ | 藏掉「插件」行 | 行过滤对 `plugins` 短路；`setPinned` 首行对 `plugins` 直接 `return`（`client.js:26`） |
| ❌ | 藏掉「更多」按钮 | 它的显隐 = `entriesOfSlot("sidebar.panellist.actions").length > 0`（`client.js:587`）。本插件注册该座位放「管理左侧栏入口…」菜单项，注册了它就会亮 |
| ❌ | 把两行合并成一个入口 | 需要自己接管 `sidebar` 座位的渲染层，那是重写侧栏外壳 |

所以左栏的**最少形态**是「插件 + 更多」两行。管理面板里「插件」显示为只读徽章「始终显示」。

## 2. 根因：pin 状态是纯内存，且只有两条下发通道

### 2.1 宿主的 pin 状态存在哪

`dsh-client-ui-sidebar/lib/client.js:17-30`：

```js
function createPanelPins() {
  const store = createSnapshotStore({ unpinned: NO_PANELS });
  const setPinned = (id, pinned) => {
    const current = store.getSnapshot().unpinned;
    if (id === "plugins" || pinned !== current.includes(id)) return;
    store.set({ unpinned: pinned ? current.filter((e) => e !== id) : [...current, id] });
  };
  return { unpinned: store, setPinned };
}
```

三点结论：

1. **纯内存**：只 `createSnapshotStore`，不读也不写 `localStorage`／不落盘，重载即回到 `[]`。
2. **`plugins` 被硬编码短路**：第一行就 `return`，任何调用都无效。
3. **幂等**：`pinned !== current.includes(id)` 时才真正 set，所以重复下发无副作用——本插件正是靠这一点做"盲推"。

### 2.2 外部能碰到 `setPinned` 的两条路

`client.js:585` 创建 `panelPins`，`:590-610` 把它包进一个工厂：

```js
const injectProps = () => ({
  startSession, toggleSidebar, selectPanel,
  setPinned: panelPins.setPinned,
  trackEntryClick,
  hooks: { panels, shortcuts, entryPins: panelPins.unpinned, entryActions },
});
```

然后 `:611` 注册 `sidebar` 座位时把它作为 `inject` 交给槽位系统。同时 `:497` 把同一个 `setPinned` 作为 `onPinnedChange` 传给「更多」菜单座位的 ownerProps。

**没有公开 service**。除这两处外，`SlotRegistry.hostFace()`（`dsh-client-ui-renderer/lib/client.js:1648-1679`）暴露的只有只读面：`subscribe`／`getVersion`／`entriesOf`／`entriesOfSlot`／`reportEntryError`／`specOf`／`isLive`／`storeOf`／`root`／`locale` 等，**不含 `setPinned`**。

### 2.3 1.0.0 为什么首屏失效

1.0.0 走的是第 2 条路（`onPinnedChange`）。而这条路的可用区间被宿主的一个渲染细节掐死了：

`dsh-client-ui-sidebar/lib/client.js:238-284` 的 `PanelMoreMenu` 把菜单内容作为 `Menu` 的 children：

```js
children: renderSlot("sidebar.panellist.actions", { entries, onOpen, onPinnedChange, onDismiss })
```

表达式在 `PanelMoreMenu` 渲染时**立即求值**（所以座位注册本身是活的），但**组件函数体**只有在 React 真正挂载那个元素时才执行。而 `Menu` 内部是：

`dsh-client-ui-primitives/lib/index.js:4373`

```js
open && jsxs(MenuSurface, { ... })
```

`open === false` 时不挂载 children → 本插件的菜单组件函数体从不执行 → `onPinnedChange` 永远拿不到 → `pinnedChannel` 一直是 `null`。

于是：**用户在点开一次「更多」之前，偏好根本无法下发给宿主**；宿主 `unpinned` 又是内存态从 `[]` 开始，首屏就是全部显示。点开一次菜单 → 组件挂载 → 通道拿到并缓存 → 之后即使菜单关闭（宿主 `setPinned` 来自 ui-sidebar `apply` 的闭包，插件生命周期内存活）也仍然可调。这正好对上"点一次「更多」才正常刷新显示"的观感。

### 2.4 为什么不能把工厂参数当作 ownerProps

曾考虑过让 `inject` 工厂接收 ownerProps，从而提前拿 `onPinnedChange`。这条路已证伪：

`dsh-client-ui-renderer/lib/client.js:435-442`：

```js
function runInject(entry, binding, actions) {
  const inject = entry.inject;
  if (!inject) return EMPTY_INJECTED_PROPS;
  const args = [];
  if (binding !== void 0) args.push(binding.key);
  if (actions !== void 0) args.push(actions);
  return bindInjectSources(inject(...args));
}
```

`sidebar.panellist.actions` 是 root scope、没声明 store，所以 `binding` 和 `actions` 都是 `void 0`，`args` 是空数组。ownerProps 是**渲染期** props，不是 inject 参数，两者根本不在一个通道上。

## 3. 方案：启动期直接取 `sidebar` 座位的 `entry.inject()`

### 3.1 关键发现

`dsh-client-ui-slots/lib/index.js:214` 注册时把 `inject` **原样存进 entry**：

```js
...options.inject !== void 0 ? { inject: options.inject } : {},
```

而 `:263-265` 的 `entries(key)` 是纯数据读取，任何时刻可调。于是：

```js
// 本插件 client.js:239-259
function grabPinnedChannel(ctx) {
  const entries = ctx.slots.entries('sidebar');
  for (const entry of entries) {
    if (!entry || typeof entry.inject !== 'function') continue;
    const injected = entry.inject();          // root scope、无参、同步
    if (injected && typeof injected.setPinned === 'function') return injected.setPinned;
  }
  return null;
}
```

**不需要接管 `sidebar` 座位**——只是调用它已经存好的工厂。这是与 B 方案（重写侧栏外壳）的本质区别。

### 3.2 三道保险

| 时机 | 手段 | 覆盖的情况 |
| --- | --- | --- |
| `apply` 最开始 | `tryAttachPinnedChannel(ctx, false)` | 常见情况：bundle 顺序让 ui-sidebar 先注册 |
| 之后 | `ctx.slots.subscribe('sidebar', …)` | 宿主晚于本插件注册 |
| 下一帧 | `requestAnimationFrame` 再抓一次 | 注册与 React 首帧时序错开导致的闪一下 |

拿到通道后立刻 `syncAllPins()` 全量下发。展示面板挂载时（`useEffect`）再 `tryAttachPinnedChannel(ctx, true)` + `syncAllPins()`，覆盖宿主重挂侧栏换出新 `setPinned` 的情况。

### 3.3 保留的兜底路

「更多」菜单仍保留 `if (typeof onPinnedChange === 'function') pinnedChannel = onPinnedChange;` 和 `reconcileEntries(entries)` 对账（用菜单拿到的 `entries` 里每行的 `pinned` 真值逐条比对）。它现在只是兜底：宿主将来若不再把 `setPinned` 放进 `sidebar` 座位的 `inject` 返回值，插件会自动退回 1.0.0 的行为（点开一次「更多」后生效），管理面板底部的提示行会重新出现。

### 3.4 数据流

```text
localStorage(唯一真相源)  ──读──>  模块内 snapshot  ──下发──>  宿主 setPinned(id, pinned)
       ↑                              ↑                              │
       └── 面板/设置页开关 ───────────┘                              ↓
                                                            宿主内存 unpinned 快照
                                                                     │
                                                                     ↓
                                                        侧栏行过滤 → 主排
```

- **单向执行**：宿主状态只是 `localStorage` 的投影，重启后由插件重新投影一遍。
- **幂等盲推**：不先读宿主状态，直接按偏好推（`setPinned` 自身幂等）。
- **只写真值**：`localStorage` 里只保留 `=== false` 的键，恢复显示时把键删掉，空对象直接 `removeItem`。

## 4. 插件是怎么装进 Web 的

### 4.1 包清单声明的两半

`package.json` 的 `dsh` 字段：

```json
"dsh": {
  "bundle": { "patch": "./cordis.patch.yml" },
  "client": { "platform": "web", "immediately": true, "inject": [] }
}
```

### 4.2 宿主半边是空实现

`index.js` 全文只有两行——本插件完全在浏览器侧工作，宿主侧不需要任何行为：

```js
// 宿主半边。
export function apply() {}
```

### 4.3 bundle patch

`cordis.patch.yml`：

```yaml
- insert:
    - id: sidebar-entry-manager
      name: '@local/dsh-sidebar-entry-manager'
```

只 `insert` 一个自己的节点，不 `disabled` 任何官方包。

### 4.4 浏览器半边如何接管

`dsh.client.immediately: true` 让 Web 客户端一启动就装载 `client.js`，无需用户打开面板。模块按 `window.__ModuleLoader__.load({ id, factory(require) {...} })` 注册，内部 `require('react')`。

### 4.5 注册的四个座位

| 座位 | 注册选项 | 作用 |
| --- | --- | --- |
| `sidebar.panellist` | `id: "sidebar-entry-manager"`, `order: 20` | 左栏入口图标（排在 `plugins` 0 / `schedules` 10 之后） |
| `main` | `key: "sidebar-entry-manager"` | 管理面板本体 |
| `sidebar.panellist.actions` | `id: "sidebar-entry-manager"`, `order: 0` | 「更多」菜单内容 + 兜底对账 |
| `settings.section` | `id: "sidebar-entry-manager"`, `order: 25` | 设置页一节，与面板共用组件 |

全部走 `ctx.slots.inject(...)`，随插件卸载一并回收。

### 4.6 样式隔离

全部 CSS 类名统一 `dsem_` 前缀，只用一个 `<style data-plugin-css="@local/dsh-sidebar-entry-manager/client.css">` 标签注入，卸载时移除。不改宿主或别的插件的任何规则。

## 5. 安装

产物：`build/dsh-sidebar-entry-manager-1.1.0.tgz`（npm pack 格式，包内 8 个文件）。

> 仓库里 `build/` 是打包产物目录，已被 `.gitignore` 忽略。若你只有源码，在仓库根目录执行 `npm pack --pack-destination build` 重新生成。

### 5.1 图形界面（推荐）

DSH 桌面端 → 左侧栏「**插件**」→ 安装 → 填 tgz 的**绝对路径**：

```text
<本仓库根目录>\build\dsh-sidebar-entry-manager-1.1.0.tgz
```

装完**完全退出并重新启动** DSH。

### 5.2 手工挂载（离线 / 排障等价路径）

1. 把 tgz 复制到 profile 的 `.plugin-manager/`；
2. 编辑 `<profile>\package.json`，`dependencies` 加一行：
   `"@local/dsh-sidebar-entry-manager": "file:.plugin-manager/dsh-sidebar-entry-manager-1.1.0.tgz"`
3. 同一文件 `dsh.profile.bundles` 数组**末尾**追加 `"@local/dsh-sidebar-entry-manager"`；
4. 在 profile 目录执行 `pnpm install`，然后完全退出并重启 DSH。

3 和 4 都不能省：只加依赖不加入 `bundles`，包在磁盘上但不会被组合进 cordis 树。

### 5.3 生效前提

- `cordis.patch.yml` 向插件树 `insert` 一个 `sidebar-entry-manager` 节点；
- `dsh.client.immediately: true` 让 `client.js` 在 Web 客户端启动即装载；
- 改代码后必须**重启 DSH**（模块世代在启动时确定，刷新页面不生效）。

## 7. 卸载与回滚

- 插件页移除，或把 `dsh.profile.bundles` 里的包名与 `dependencies` 那行删掉后 `pnpm install` + 重启；
- 偏好残留在浏览器 `localStorage` 的 `dsh-sidebar-entry-manager:prefs` 键里（无副作用，键名唯一）。彻底清干净：

```js
localStorage.removeItem('dsh-sidebar-entry-manager:prefs')
```

宿主的 `plugins` 行、`Menu` 组件、其它插件文件**均未被改动**，无需还原任何东西。

## 8. 失效条件与维护

| 宿主改动 | 后果 | 本插件表现 |
| --- | --- | --- |
| `sidebar` 座位不再在 `inject` 返回值里给 `setPinned` | 主通道失效 | 自动退回「更多」菜单 `onPinnedChange` 路径（点开一次菜单后生效），面板底部提示行重现 |
| `sidebar.panellist` 改名为别的 key | 入口图标不出现 | 需改 `client.js` 里四处 `ctx.slots.inject(...)` 的 key |
| 行过滤不再读 `unpinned` | 隐藏能力失效 | 需重新找 pin 下发点 |
| `Menu` 改为始终挂载 children | 无影响 | 兜底路更早可用 |

复核方法：读宿主 `dsh-client-ui-sidebar/lib/client.js` 的 `createPanelPins()`（约 :17-30）和 `apply`（约 :560-656），确认 `injectProps` 是否仍返回 `setPinned`。
